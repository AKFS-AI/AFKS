Title: StageHierarchy - 폴더 구성 및 문서 작성 가이드
Version: v2.1
Owner: 기획/개발 공용

0) 목적
- 초보자도 텍스트만 보고 씬을 제작/배선할 수 있도록, 문서 구조/작성 규칙/검수 체크리스트를 표준화한다.

0.1) v2.0 업데이트(월드 스프라이트 모드 전환)
- 기본 제작 방식은 UI 프리팹 체인 대신 ‘월드 스프라이트 + 콜라이더’ 중심으로 단순화한다.
- UI는 오버레이(클로즈업/설정/자막 등) 전용으로 사용하며, 일반 상호작용은 전부 스프라이트 클릭으로 처리한다.
- 권장 컴포넌트 매핑:
  - 이동/문: BoxCollider2D + HotspotMove
  - 체인 상호작용: BoxCollider2D + ClickHandler + ChainController
  - 문서/사진 확대: BoxCollider2D + HotspotInspect(spawnUIPrefab=false) 또는 DocumentCloseup
  - 점프스케어: BoxCollider2D + JumpscareTrigger
- CloseupPanel UI 체인은 선택 요소로 유지한다(정밀 클릭 필요 시만). 문서에서는 [월드 모드]를 우선 기술하고, UI 체인은 [옵션] 섹션으로 분리한다.

1) 폴더 구조(권장)

- Menu_Hierarchy.txt               : 메인 메뉴 씬(MainMenu)
- Stage_1_Front_Hierarchy.txt      : 스테이지 1(병원 앞, Scene=Stage1)
- Stage_2_Lobby_Hierarchy.txt      : 스테이지 2(로비, Scene=Stage2)
- Stage_3_Office_Hierarchy.txt     : 스테이지 3(관리실)
- Stage_4_Delivery_Hierarchy.txt   : 스테이지 4(분만실)
- Stage_5_Nursery_Hierarchy.txt    : 스테이지 5(신생아실)
- Stage_6_Chapel_Hierarchy.txt     : 스테이지 6(기도실)
- StageHierarchy_Guide.txt         : 본 가이드(이 파일)

2) 파일 네이밍 규칙
- 씬별 문서: Stage_<Index>_<Name>_Hierarchy.txt (문서용 규칙)
  예) Stage_1_Front_Hierarchy.txt, Stage_2_Lobby_Hierarchy.txt
- 실제 씬 파일(코드 기준): MainMenu, Stage1, Stage2, (이후) Stage_Office 등. StageIds는 실제 씬 이름과 1:1 일치해야 함.
- 공통/특수: Core_Hierarchy.txt, Menu_Hierarchy.txt
- 메타 파일(.meta)은 Unity가 자동 관리한다.

3) 문서 본문 섹션 표준(순서 고정)
1. 하이라키어 최종 구조도 — 전체 구조를 한눈에
2. 하이라키어 제작 절차(1:1 매핑) — 번호별 생성 경로/컴포넌트 추가
3. 인스펙터 설정 — 오브젝트별 핵심 수치·토글을 표식으로
4. Components & Wiring — 참조/이벤트 연결을 화살표(←/→)로 표기
5. Build Settings — 씬 등록·순서
6. Tests — 정상/엣지/예외 간단 시나리오
7. 체크리스트 — ‘예/아니오’ 확인 포인트
8. FAQ — 자주 막히는 증상→원인→조치
9. 변경 이력 — 버전/날짜/요약(최대 3줄)

4) 오브젝트 카드 템플릿(반복 사용)
- 이름:
- 생성 경로: (예: GameObject > UI > Canvas)
- 필요한 컴포넌트: (예: Canvas, CanvasScaler, CanvasGroup, FadeCanvas)
- 인스펙터 기본값: (핵심 수치/플래그)
- 배선/참조: (예: SceneService.FadeCanvas ← FadeCanvas 드래그 연결)
- 확인 포인트: (씬 재생 전/후 체크)

5) 작성 규칙
- ‘무엇을 만든다 → 어떻게 만든다(생성 경로) → 인스펙터 값 → 연결(배선) → 확인’ 순서로 쓴다.
- 초보자 기준으로 모든 생성 경로를 메뉴 풀 경로로 표기한다.
- 수치/토글은 기본값과 권장값을 함께 명시한다.
- Stage ID, 씬 이름, 버튼 메서드 등 ‘문자열/식별자’는 정확히 표기한다.

5.1) 표기 규칙(이름_객체정보(컴포넌트))
- 최종 구조도와 절차의 각 줄은 다음 형식을 사용한다.
  - 이름_객체정보(컴포넌트)
  - 예: MainCanvas_UI/Canvas(Canvas, CanvasScaler, GraphicRaycaster)
       CloseupImage_UI/Image(Image, AspectRatioFitter)
       ChainRoot_Empty(-)
- 객체정보는 생성 메뉴 경로의 요약이다.
  - UI/Button, UI/Image, UI/Canvas, UI/TextMeshPro, UI/Event System
  - 2D/Sprite, 3D/Cube 등 엔진 기본 객체
  - Empty = GameObject > Create Empty로 만든 빈 오브젝트
- 컴포넌트는 대괄호 대신 괄호로 나열한다. 필요 없으면 (-)로 표기한다.
- 구조↔절차 일치: ‘최종 구조도’와 ‘제작 절차’는 동일한 순서/들여쓰기를 유지한다.

5.2) 표 스타일(읽기 쉬운 기호 규칙)
- [Components] = 실제 컴포넌트 이름 나열, [Inspector] = 핵심 속성만 불릿으로 (기존 문서 호환용)
- 참조 연결 표기: Consumer.Field ← Provider, 이벤트: Button.OnClick → Receiver.Method()
- 값=권장값(설명) 형태를 유지. 예) Alpha=0.65(배경 반투명)

5.3) 텍스트 렌더링(TextMeshPro) 규칙
- 모든 UI 텍스트는 TextMeshPro 사용을 기본으로 한다.
- 생성 경로 표기: UI > Text - TextMeshPro
- 폰트 에셋/스타일은 공통 프리셋 사용(예: Body, Heading). 프리셋 이름을 문서에 명시한다.
- 권장 인스펙터 값
  - TextMeshProUGUI
    - Font Asset = <공통 폰트>
    - Font Style = <Body|Heading 프리셋>
    - Auto Size = On (Min=24, Max=40)  ; 해상도 호환
    - Overflow = Ellipsis  ; 넘침 시 말줄임표
    - Alignment = Middle Center
    - Rich Text = On (필요 시)
    - Raycast Target = Off (버튼 라벨은 클릭 차단 방지)

5.4) 버튼/라벨 표준(템플릿)
- Button_* (UI/Button)
  - [Components] Button, Image
  - [Inspector(Button)] Interactable=On, Transition=Color Tint(기본)
  - Label (UI/Text - TextMeshPro)
    - [Components] TextMeshProUGUI
    - [Inspector] 위 5.3 권장값 적용
  - 배치: Label은 Button 자식으로 중앙 정렬, Stretch 사용 금지(텍스트 깨짐 방지)

5.5) 접근성·가독성 체크
- 터치 타겟 최소 44x44 px 이상
- 대비: 텍스트/배경 명도 대비 4.5:1 이상 권장
- 깜빡임/과도한 모션 지양, 설정에서 감소 옵션 제공
- 현지화 대비: 문구 하드코딩 지양, 문자열 리소스화(후속)

5.6) 정렬 정책(Stable Ordering)
- 목적: 새 항목이 추가되지 않았는데도 하이라키어 순서가 바뀌는 일을 방지한다.
- 정렬 키 = (역할 우선순위, 이름 알파벳 A→Z)
  - 역할 우선순위(예시, 범용): Services(전역/전환/입력 등) > Controllers > UI(View/Panel/Button 등) > Data/ScriptableObject > Empty(컨테이너) > Optional
  - 같은 우선순위 안에서는 오브젝트 이름을 알파벳 오름차순으로 정렬한다(한글은 로마자 표기 또는 파일명 기준).
- 표기는 하이픈 트리(불릿)만 사용하고, 번호는 사용하지 않는다.
- 신규 항목은 정렬 키 위치에 ‘삽입’한다. 기존 항목의 상대 순서가 바뀌지 않도록 한다.

5.7) 컨테이너 정책(Container Objects)
- 목적: 하이라키 가독성/변경 안정성 향상. 실제 씬에서도 분류 단위를 “빈 컨테이너 GameObject”로 둔다.
- 원칙
  - 컨테이너는 Empty(GameObject > Create Empty)로 만들고, Transform은 Reset(0,0,0 / 1,1,1).
  - 컨테이너에는 컴포넌트를 붙이지 않는다(폴더 역할 전용).
  - 컨테이너 이름 예: `Services`, `UI`, `World`, `Data`, `Empty` 등. 팀에서 승인한 집합만 사용.
  - 정렬 정책(5.6)을 컨테이너 내부 자식에도 동일 적용.
  - EditorOnly 이름은 사용하지 않는다(자식까지 빌드 제외 위험).

5.9) 전역 컴포넌트 단일성(Global Singletons)
- EventSystem: ‘씬마다 1개’를 원칙으로 배치하되, 애디티브 전환 시 활성 인스턴스는 항상 1개만 유지한다(GlobalSingletonGuard가 나머지를 자동 비활성화).
- AudioListener: 활성 인스턴스 1개 유지(일반적으로 현재 활성 카메라). 다른 씬 카메라는 비활성화되거나 언로드된다.

5.10) 해상도/PPU/카메라 규칙(배경 스케일링)
- 용어: PPU(Pixels Per Unit) = 스프라이트 픽셀/월드 1유닛 비.
- 월드 크기: worldWidth=imgWidth/PPU, worldHeight=imgHeight/PPU
- 카메라(Orthographic): 세로 유닛 = 2×Size, 가로 유닛 = 2×Size×(ScreenWidth/ScreenHeight)
- 맞춤 방식
  - Fit Height(전체 표시): Size = imgHeight ÷ (2×PPU)  ; 좌우 여백 허용
  - Aspect Fill(가득 채우기): Size = (imgWidth/PPU) ÷ (2×aspect)  ; 일부 크롭, aspect=ScreenWidth/ScreenHeight
  - Stretch(강제 맞춤, 왜곡 허용): 카메라 Size는 목표 세로 기준, BG.Scale로 보정
    - scaleX = (targetWidth/PPU) ÷ worldWidth,  scaleY = (targetHeight/PPU) ÷ worldHeight
    - 예: 원본 1536×1024, 목표 1920×1080, PPU=100 → scaleX=1.25, scaleY≈1.0547

5.11) 체인 상호작용 + 단계적 해금 패턴(문/쇠사슬)
- 개요: 조건/효과 시스템을 사용해 ‘정확한 클릭 순서·횟수’로 이벤트를 해금한다.
- 구성(권장):
  - 입력/라우팅: ClickHandler + ClickToEventRouter → StageEventSystem.OnObjectClicked(objectId)
  - 데이터: StageDefinition(StageEvent[]) + StageEvent(conditions[], effects[])
  - 조건: ClickCountCondition, AggregateClickCountCondition, ClickSequenceCondition
  - 효과: EnableInteractableEffect, ChainShakeThenBreakEffect, StageTransitionEffect
- 흐름(예시, Stage1): Door 클릭→ZoomEvent 실행→효과로 체인 인터랙션 활성 → 체인 합계 5회 달성 후 체인 클릭 시 체인 분리 이벤트 실행(흔들림→분리)→ autoProceed로 다음 이벤트 준비 → Door 클릭 시 Stage2로 전환
- 월드 스프라이트 기반: UI 체인 대신 월드 스프라이트 + 콜라이더로 직접 상호작용

5.13) 전문 디버깅(권장 설정)
- 입력/레이캐스트: InputService.debugLogging=On → 클릭 경로, UI 차단 여부 로그
- 클로즈업 패널: HotspotInspect.debugLog=On → Canvas 선택/프리팹 생성·재사용 경로 확인
- 자동 와이어링: CloseupPanelAutoWire.debugLog=On → CloseupImage/ChainHotspot/DoorHotspot 배선 및 BG 자동 매핑 결과 확인
- 중복 생성 가드: 동일 Canvas 내 ChainCloseupController가 있으면 재생성 금지(Log 없음이면 정상)
- 전역 단일성: GlobalSingletonGuard/SceneService 로그로 EventSystem/AudioListener 활성 인스턴스 1개 유지 확인
- 각 씬은 `MainCanvas` 1개 + `EventSystem` 1개를 가진다.
- 클로즈업 오버레이는 `CloseupPanel`(Canvas 없음) 프리팹을 `MainCanvas` 하위에 배치하는 것을 권장한다.
- CanvasScaler 표준: ReferenceResolution=1920×1080, Screen Match=Match Width Or Height, Match=1.0(Height).

6) 검수 체크리스트(공통)
- [ ] 하이라키 트리와 실제 오브젝트 구성이 일치한다.
- [ ] 필수 컴포넌트가 누락되지 않았다(CanvasGroup, Collider2D 등).
- [ ] 배선이 연결됐다(Button.OnClick, SceneService.FadeCanvas 참조 등).
- [ ] Build Settings에 씬이 등록되고 순서가 맞다(Core → MainMenu → Stage1 → Stage2 ...).
- [ ] 실행 검증 시 전환/페이드/입력이 정상 동작한다.
- [ ] 전역 단일성: EventSystem=1, AudioListener=1 유지.

5.8) 인스펙터 미러링(Inspector Mirroring)
- 목적: 문서의 ‘3) 인스펙터 설정’ 섹션이 실제 Unity 인스펙터 화면과 1:1로 일치하도록 한다.
- 규칙
  - 오브젝트 단위로 하이라키 순서를 그대로 따르며, 각 오브젝트 섹션의 항목 순서는 다음과 같다.
    1) Transform  →  2) 기타 엔진 컴포넌트(Canvas, Image, Button 등)  →  3) 스크립트 컴포넌트(알파벳순 아님, 실제 추가 순서)
  - 컴포넌트 내부 속성은 실제 인스펙터의 레이블명을 그대로 사용한다. [InspectorName]이 지정된 경우 해당 한글 라벨로 표기한다.
  - 스크립트의 직렬화 필드는 코드 선언 순서대로 표기한다.
  - 각 속성은 ‘현재 기본값 = 권장값(설명)’ 형식으로 기입한다. 값이 비워도 되는 참조는 “None(옵션)”으로 명시한다.
  - 체크박스/드롭다운/오브젝트 참조/수치값을 구분해 표기하고, 단위(초, px 등)를 함께 적는다.
  - 동일 오브젝트 내 자식의 인스펙터는 자식 오브젝트 항목에서 별도로 기술한다.
  - 정합 규칙: 1) 최종 구조도, 2) 제작 절차, 3) 인스펙터 섹션은 반드시 동일한 오브젝트 순서를 사용한다.
  - Canvas 상위 규칙: UI 렌더링이 필요한 모든 UI 컴포넌트(Image, Text, Button, CanvasGroup 등)는 상위에 Canvas가 반드시 있어야 한다. CloseupViewer 같은 CanvasGroup 기반 오브젝트도 부모 체인에 Canvas가 존재해야 한다.
  - 예시(간단)
    - FadeCanvas (UI/Canvas)
      - Transform
      - Canvas
        - Render Mode = Screen Space - Overlay
      - Canvas Scaler
        - Reference Resolution = 1920x1080
      - Graphic Raycaster = 기본값
      - Canvas Group
        - Alpha = 0
      - Fade Canvas(스크립트)
        - 캔버스 그룹 = 자기 자신(CanvasGroup)

7) 링크/참조(코드 개념)
- 전환 서비스: SceneService(Fade.Out → LoadAdditive → Activate → Unload → Fade.In)
- 페이드 UI: FadeCanvas(CanvasGroup 알파/입력 차단)
- 입력/라우팅: ClickHandler → ClickToEventRouter → StageEventSystem.OnObjectClicked
- 데이터: StageDefinition.LoadFromDefinition → StageEventSystem(eventSequence)
- 조건/효과 유틸: StageEventSystem.GetClickCount / DoesClickHistoryMatch / SetObjectInteractable
- 카메라 줌: CameraZoomEffect(표준)
- 스테이지 루트: StageRoot(Initialize/Teardown 훅)
- 스테이지 ID: StageIds(Menu=MainMenu, Front=Stage1, Lobby=Stage2, Office/Delivery/Nursery/Chapel)

8) 변경 시 원칙
- 변경 시 해당 씬 문서의 관련 섹션을 즉시 업데이트한다.
- 새 오브젝트/기능 추가 시 ‘오브젝트 카드’로 항목을 추가한다.
- 큰 변경은 문서 상단 Version을 올리고 변경 요약을 3줄 이내로 기록한다.

예) Core_Hierarchy.txt의 FadeCanvas 카드 요약
- 생성 경로: UI/Canvas 생성 → 하위에 UI/Image 추가 → CanvasGroup, FadeCanvas 추가
- 인스펙터: Canvas RenderMode=Overlay, SortingOrder=1000 / CanvasGroup Alpha=0
- 배선: SceneService.FadeCanvas ← FadeCanvas 드래그
- 확인: 플레이 중 전환 시 화면이 검게 페이드되며 입력이 차단된다.

10) 유지 보수
- 문서와 씬/코드가 어긋나면 문서 우선 업데이트 후, 씬/코드를 맞춘다.
- 정기 점검(스프린트 말): 모든 씬 문서의 체크리스트 통과 스크린샷/로그를 첨부한다.

11) 범위·대상(Scope & Audience)
- 대상: Unity 초보~중급 실무자. 텍스트만으로 씬 제작·배선을 완료할 수 있어야 한다.
- 범위: Core/Menu/Stage_* 씬의 하이라키/인스펙터/배선/빌드/검증 규칙. 아트·오디오 상세는 별도 가이드 참조.

12) 용어(Glossary)
- 씬(Scene): Unity의 로드 단위. Core는 상주, Stage_*는 애디티브 로드/언로드.
- 오브젝트 카드(Object Card): 개별 오브젝트의 생성 경로/컴포넌트/인스펙터/배선/확인을 표준화한 블록.
- 배선(Wiring): 컴포넌트 간 참조 연결 및 이벤트(OnClick 등) 바인딩.
- ID: 씬 이름 또는 StageIds 상수와 동일한 문자열 식별자.

13) 표준 규칙(Standard Rules)
- MUST: 문서 섹션 순서를 유지하고 누락 없이 작성한다.
- MUST: 생성 경로를 메뉴 풀 경로로 표기한다(예: GameObject > UI > Canvas).
- MUST: 중요한 수치(해상도, Alpha, Sorting Order)는 값과 의미를 함께 적는다.
- MUST: Build Settings 등록/순서를 명시하고 검증 체크리스트에 포함한다.
- SHOULD: 이름은 의도를 드러내며 UpperCamelCase(오브젝트), SNAKE_CASE(상수)를 따른다.
- SHOULD: 공통 UI 스케일(1920x1080, Match 1.0/Height)을 유지한다.

14) 식별자·네이밍 정책(IDs & Naming)
- 씬 이름: Core, MainMenu, Stage1, Stage2, 이후 Stage_Office/Stage_Delivery/Stage_Nursery/Stage_Chapel
- 스테이지 상수: StageIds.Menu/Front/Lobby/Office/Delivery/Nursery/Chapel
- 오브젝트: 기능 기반 UpperCamelCase (예: FadeCanvas, SceneService, StartupLoader)
- 파일: Stage_<Index>_<Name>_Hierarchy.txt, Core_Hierarchy.txt, Menu_Hierarchy.txt

15) 씬 분류·수명주기(Scene Taxonomy & Lifecycle)
- Core: 상주. 서비스 등록/전환/페이드/입력락 유지.
- MainMenu: 진입 UI. 버튼 → GameEvents.StageChangeRequested 발행. 저장이 없으면 Continue는 숨김.
- Stage_*: 애디티브 로드/활성/이전 언로드. StageRoot로 진입/종료 훅 제공.
- 전환 순서: Input.Lock → Fade.Out → LoadAdditive(next) → Activate → Unload(prev) → Fade.In → Input.Unlock

16) 제작 워크플로우(Authoring Workflow)
- 작성: 오브젝트 카드를 우선 작성 → 씬에 반영 → 체크리스트 통과.
- 변경: 문서 먼저 수정 후 씬/코드 정합화. 변경 요약(3줄) 기록.
- 리뷰: 문서와 씬 캡처, Build Settings 스크린샷 첨부. 체크리스트 결과 포함.

17) 품질 게이트(Definition of Done)
- [ ] 문서 섹션 표준을 모두 채웠다.
- [ ] 오브젝트 카드가 누락 없이 유효하다.
- [ ] Build Settings 등록/순서 스샷 첨부(Core→MainMenu→Stage1→Stage2).
- [ ] 실행 검증: MainMenu→Stage1 전환이 페이드와 입력락을 동반해 3회 이상 성공.
- [ ] 콘솔 Error 0, Warning 허용 범위 내(설명 기재).

18) 검증 매트릭스(Validation Matrix)
- 정상: 메뉴 버튼 3종(New/Continue/Quit) 동작, FrontDoor 클릭 전환(Stage1→Stage2).
- 엣지: 빠른 연타, UI 위 클릭 무시, 씬 미등록 시 실패 로그.
- 예외: 잘못된 Stage ID → 이전 상태 유지 + 페이드 해제 + 로그.
- 성능: 전환 < 1.5s, 전환 중 GC/에러 0(기본 리소스 기준).

19) 샘플 오브젝트 카드(채워진 예)
- 이름: FadeCanvas
- 생성 경로: GameObject > UI > Canvas (하위 Image 추가), Add Component: CanvasGroup, FadeCanvas
- 필요한 컴포넌트: Canvas, CanvasScaler, GraphicRaycaster, Image, CanvasGroup, FadeCanvas
- 인스펙터 기본값: Canvas(Render Mode=Overlay, Sorting Order=1000), CanvasScaler(1920x1080, Match 0.5), Image(Color #000,A=1), CanvasGroup(Alpha 0, Interactable Off, Blocks Off)
- 배선/참조: SceneService.FadeCanvas ← FadeCanvas 드래그 연결
- 확인 포인트: 전환 시 화면이 검게 페이드되고 입력이 차단됨

20) 부록: 통합 체크리스트(요약)

- [ ] Build Settings 등록/순서 OK

2.2 (1.1) <Child_A>

  - Add Component: <...>

4) Components & Wiring(참조/이벤트 배선)

5) Build Settings(Scenes In Build)
